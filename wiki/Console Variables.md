Console Variables (CVars) are variables that can be set by environment variables, the command line, or at runtime to control engine systems.

Supported types are:
- Integer
- Float
- Boolean
- String
- Enum
# Declaration
All CVars should be declared as static variables with names in a [[#^a7d14b|standardised format]].

Integers, floats, booleans, and strings support simple declarations with names, defaults, descriptions, and optional [[#flags]]. No additional work is required to register a variable.
```cpp
// Simple
Cvar::Int WindowWidth("window.width", 1280, "Window width", Cvar::Flags::Unsigned);
Cvar::Int WindowHeight("window.height", 720, "Window height", Cvar::Flags::Unsigned);
```

Enumerations additionally require a mapping of names and descriptions to their values. An empty string for a description is treated as null.
```cpp
// Enum
Cvar::Enum<vk::PresentModeKHR> VsyncMode(
    "render.vsync", vk::PresentModeKHR::eMailbox,
    "VSync mode, prevents screen tearing",
    {
        {"None", "Present frames immediately, may cause tearing",
          vk::PresentModeKHR::eImmediate},
        {"LowLatency", "", vk::PresentModeKHR::eMailbox},
        ...
    });
```

All variable types support dynamically assigned defaults via a function and a description of how this value is obtained (see [[#^77f0ff|conventions]]). This will be evaluated during startup.
```cpp
// Dynamic defaults
static std::string defaultDataDir() { ... }
Cvar::String DataDirectory("core.data_directory", defaultDataDir,
                            "${exe_directory}/assets",
                            "Path of data directory",
                            Cvar::Flags::InitOnly);
```

# Assignment
A CVar can be assigned, in order of highest to lowest precedence:
- Runtime changes, which trigger any [[#change callbacks]].
- Command line, in the format `var.name value`.
- Environment variables, names formatted in `VN_VAR_NAME` e.g., `debug.validation_layers` would become `VN_DEBUG_VALIDATION_LAYERS`.
- Defaults, either constants or generated by [[#^c48a5e|a function]].
# Validation
Variables may be validated using callbacks, registered during system initialisation, or [[#flags]] such as `Unsigned`. These take the form of a function that returns `std::nullopt` if valid, or a string describing the error if invalid.
```cpp
maxTextures.getStore().addValidate(
  [this](int capacity) -> std::optional<std::string> {
	if (capacity < mData.size())
	  return "Cannot be smaller than current size (" +
			 std::to_string(mData.size()) + ")";
	return std::nullopt;
  });
```
> [!warning]
> [[#Assignment]] from the CLI/environment occurs before validation callbacks are registered. Therefore callbacks cannot validate the CLI.
# Change Callbacks
Any change callbacks registered with a variable are executed immediately after any runtime update to bring systems in line with new configuration. They are passed the new value as context.
```cpp
LogLevel.getStore().addChange([](auto level) { spdlog::set_level(level); });
```
# Flags
- `InitOnly`: The variable can only be set during initialisation. Any changes require a restart to apply. This **DOES NOT** prevent runtime changes, only signify that they have no effect.
- `Unsigned`: The variable cannot be negative.
# Conventions
- Variables **MUST** be named in the form `section.variable_name` ^a7d14b
- Dynamic defaults **MUST** have values described using JavaScript template literal notation (`${interpolated}`). ^77f0ff
